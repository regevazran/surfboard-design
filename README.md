# Surfboard Color Studio v2.0

אפליקציית Web סטטית לסימון אזורים בתמונת גלשן, שינוי צבעים תוך שמירת הצללות/ברק, שמירה בענן ושיתוף פרויקט לעריכה דרך קישור.

## מה השתנה ב-v2.0

- **הפרויקטים שלי עברו מ-localStorage ל-Supabase**: לאחר כניסה לחשבון הבעלים מוצגים כל הפרויקטים השייכים לחשבון מכל מחשב או טלפון.
- נוסף **Supabase Auth** עם כניסת אימייל/סיסמה לבעלים.
- לכל פרויקט נוסף `owner_id`.
- נשאר **סוג קישור אחד בלבד — קישור עריכה**.
- אדם שמקבל קישור עריכה יכול לפתוח, לערוך ולשמור **רק את הפרויקט שבקישור**; אין לו גישה לרשימת הפרויקטים של הבעלים.
- `view_token_hash` וקישור "צביעה בלבד" הוסרו.
- בעל הפרויקט יכול לפתוח, לשמור, לשתף ולמחוק פרויקטים מתוך "הפרויקטים שלי".
- כניסת Supabase נשמרת בדפדפן, ולכן בדרך כלל אין צורך להתחבר מחדש בכל פתיחה.

## לפני שמעלים את הקבצים ל-GitHub

### 1. צור משתמש בעלים ב-Supabase

ב-Supabase Dashboard:

1. פתח **Authentication -> Users**.
2. צור משתמש עם האימייל והסיסמה שבהם תרצה להשתמש באפליקציה.
3. מומלץ לעשות זאת **לפני** הרצת `supabase-setup.sql`.

האפליקציה עצמה אינה כוללת כפתור Sign Up. משתמשים שקיבלו קישור עריכה אינם צריכים חשבון.

### 2. הרץ את `supabase-setup.sql` החדש

1. פתח **SQL Editor** ב-Supabase.
2. העתק את כל התוכן של `supabase-setup.sql` והריץ אותו.
3. הסקריפט מבצע migration לגרסה הישנה ואינו מוחק את התמונה או `project_data` של הפרויקטים הקיימים.

#### מה יקרה ל-top / top 2 / top 3 הקיימים?

אם בזמן הרצת ה-SQL קיים **בדיוק משתמש Auth אחד**, כל הפרויקטים הישנים שאין להם `owner_id` ישויכו אליו אוטומטית. לכן `top`, `top 2`, `top 3` אמורים להופיע ב-"הפרויקטים שלי" לאחר הכניסה.

אם הרצת את ה-SQL לפני יצירת המשתמש, אפשר פשוט ליצור את המשתמש ואז **להריץ שוב את אותו SQL**.

אם קיימים כבר כמה משתמשי Auth, ההקצאה האוטומטית לא מתבצעת כדי לא לשייך פרויקטים לאדם הלא נכון. במקרה כזה מצא את האימייל של הבעלים והריץ פעם אחת:

```sql
update public.surfboard_projects
set owner_id = (
  select id
  from auth.users
  where email = 'YOUR-OWNER-EMAIL'
  limit 1
)
where owner_id is null;
```

החלף את `YOUR-OWNER-EMAIL` באימייל של חשבון הבעלים.

### 3. העלה את קבצי v2.0 ל-GitHub

החלף ב-repository את:

- `index.html`
- `app.js`
- `styles.css`
- `supabase-setup.sql`
- `README.md`

**אל תחליף את `config.js` שלך** אם כבר הכנסת בו את ה-Project URL וה-Publishable key הנכונים.

אין שינוי נדרש ב-`manifest.webmanifest`.

## איך המערכת עובדת עכשיו

### בעלים

בכניסה רגילה לאתר, אם אין session שמור, יופיע חלון כניסה. לאחר התחברות:

- "הפרויקטים שלי" נטען מ-Supabase.
- הרשימה זהה בכל מכשיר שבו נכנסים לאותו חשבון.
- ניתן לפתוח כל פרויקט, להעתיק קישור עריכה או למחוק אותו.
- פרויקט שנפתח דרך הרשימה נטען באמצעות הרשאת הבעלים ולא דורש token בתוך ה-URL.

כתובת בעלים של פרויקט נראית בערך כך:

```text
https://USERNAME.github.io/surfboard-color-studio/?p=PROJECT_ID
```

הכתובת הזו לבדה **אינה** נותנת לאדם אנונימי גישה לפרויקט.

### שיתוף לעריכה

לחיצה על **קישור עריכה** יוצרת כתובת בסגנון:

```text
https://USERNAME.github.io/surfboard-color-studio/?p=PROJECT_ID&mode=edit#t=EDIT_TOKEN
```

מי שמחזיק בקישור יכול:

- לראות את הפרויקט הזה.
- לשנות צבעים ומסכות.
- לשמור שינויים לאותו פרויקט.
- לייצא PNG.

הוא **לא** יכול לקבל דרך הקישור את רשימת הפרויקטים שלך או לפתוח פרויקט אחר בלי token מתאים.

## תאימות לפרויקטים וקישורים ישנים

- קישורי **עריכה** ישנים ממשיכים לעבוד כל עוד ה-edit token שלהם נשאר זהה.
- אם הדפדפן הנוכחי עדיין מכיר edit token ישן דרך רשימת v1.x המקומית, v2.0 מנסה לשמר אותו אוטומטית בחשבון.
- בפרויקט ישן שבו אין יותר עותק של ה-edit token, הפעם הראשונה שבה הבעלים מבקש קישור עריכה חדש תיצור token חדש וקבוע. במקרה כזה קישור עריכה ישן לאותו פרויקט, אם עדיין קיים במקום אחר, יפסיק לעבוד.
- קישורי "צביעה בלבד" של v1.x אינם נתמכים ב-v2.0, בהתאם למעבר לסוג קישור יחיד.

## אבטחה

- `config.js` צריך להכיל רק **Publishable key / anon key**, לא `service_role` או Secret key.
- טבלת `surfboard_projects` אינה ניתנת לקריאה ישירה ל-`anon` או `authenticated`; הגישה נעשית דרך RPC functions מוגבלות.
- פעולות בעלים בודקות `auth.uid()` מול `owner_id`.
- פעולות דרך קישור משותף בודקות hash של edit token ומוגבלות ל-`project_id` שבקישור.
- `edit_token_secret` נשמר במסד כדי שהבעלים המחובר יוכל לקבל את אותו קישור שיתוף גם ממכשיר אחר. הוא אינו מוחזר למשתמש אנונימי דרך ה-API של האפליקציה.

## פיתוח מקומי

```bash
python3 -m http.server 8080
```

ואז:

```text
http://localhost:8080
```

פתיחה ישירה כ-`file://` אינה מומלצת בגלל Clipboard, Share וקריאות רשת.
